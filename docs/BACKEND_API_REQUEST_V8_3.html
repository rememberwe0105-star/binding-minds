P2 A. Accounting & Xero Sync — Growth 유료 기능

무엇인가요?

Stripe가 기관 계좌로 입금하는 payout이 어떤 기부금과 수수료로 구성됐는지 정리해, NZ에서 가장 널리 쓰이는 회계 소프트웨어 Xero로 보내는 기능입니다. 방식은 검토 결과 플랫폼 → Xero API 직접 단방향 sync로 확정했습니다 (Zapier 방식은 payout summary 로직이 어차피 내부에 필요 + 기관별 유료 계정 요구로 부적합. Donorfy/Keela와 같은 업계 표준 패턴입니다). Xero에서 읽는 것은 계정과목(COA)뿐이고, 거래 데이터는 플랫폼→Xero 한 방향으로만 흐릅니다.

A-1. Stripe payout 집계

  • Stripe webhook payout.paid 수신 → balance transaction 조회로 payout별 구성 내역(기부 총액/건수, Stripe 수수료, 플랫폼 수수료, 조정) 집계·저장
  • GET /api/v1/me/charity/payouts — payout summary 목록/상세 (Growth 전용)

A-2. 환불·chargeback 기록 (조정 라인)

  • webhook charge.refunded, charge.dispute.* 수신 → 해당 payout에 조정 내역 기록
  • 플랫폼 내 환불 요청/승인 기능은 만들지 않습니다 — 기관이 Stripe 대시보드에서 직접 처리 (Donorbox 운영 모델). 우리는 기록·표시만 합니다

P3 B. 기관 프로필 메타데이터 (업데이트 4 신규 — 가벼운 작업)

Charities 목록에 정렬 옵션(Recently updated / Name A–Z / Claimed profiles first)이 추가됐습니다. 지금은 프론트 로컬 데이터로 동작하며, 추후 기관 API 연동 시 아래 필드가 응답에 포함되면 실데이터 정렬로 자연스럽게 전환됩니다.

  • 기관 목록/상세 응답에 profile_updated_at 추가 — 프로필 정보가 마지막으로 관리/갱신된 시각
  • 기관 목록/상세 응답에 claim_status 추가 (unclaimed | claimed | partnered) — 기존 승인 파이프라인 상태와 매핑
  • 프로필 수정·승인·티어 변경 등 관리 이벤트 발생 시 profile_updated_at 갱신
