안녕하세요, 백엔드 팀 여러분. v8.0/v8.1 반영에 집중하고 계신 것 알고 있어서, 이 문서는 일정을 재촉하는 것이 아니라 다음 로드맵을 미리 공유하는 목적입니다. 🙏

Growth(유료) 플랜의 핵심 기능으로 회계 연동을 준비하고 있습니다. Stripe가 기관 계좌로 입금하는 payout이 어떤 기부금과 수수료로 구성됐는지를 정리해서, NZ에서 가장 많이 쓰는 회계 소프트웨어인 Xero로 보내는 기능입니다. 프론트 데모(대시보드 Accounting 탭)는 이미 배포되어 있어 화면을 보면서 이야기할 수 있습니다.

방식 결정 — Xero API 직접 단방향 sync (Zapier 아님)

선택지평가
Option 1 — Zapier 경유payout summary 생성 로직은 어차피 플랫폼 내부에 필요 + 기관마다 Zapier 유료 계정 필요 + 오류 추적 어려움 → 유료 기능으로 팔기엔 신뢰성 부족
Option 2 — Xero API 직접 (채택)Donorfy/Keela와 같은 업계 표준 패턴. Xero에서 읽는 건 계정과목(COA)뿐, 거래는 플랫폼→Xero 단방향 (Xero 수정 내용 역동기화 불필요)

P2 부탁드리는 작업

1. Stripe payout 집계

  • Stripe webhook payout.paid 수신 → balance transaction 조회로 payout별 구성 내역(기부 총액/건수, Stripe 수수료, 플랫폼 수수료, 조정) 집계·저장
  • GET /api/v1/me/charity/payouts — payout summary 목록/상세 (Growth 전용)

2. 환불·chargeback 기록 (조정 라인)

  • webhook charge.refunded, charge.dispute.* 수신 → 해당 payout에 조정 내역 기록
  • 플랫폼 내 환불 요청/승인 기능은 만들지 않습니다 — 기관이 Stripe 대시보드에서 직접 처리 (Donorbox 운영 모델). 우리는 기록·표시만 합니다

3. Xero 연동 (Growth 전용)

MethodEndpoint설명
POST/api/v1/me/charity/xero/connectOAuth2 연결 시작 (redirect flow)
DELETE/api/v1/me/charity/xero/connect연결 해제
GET/api/v1/me/charity/xero/accounts계정과목(COA) 조회
PUT/api/v1/me/charity/xero/mapping매핑 저장 — 기부수입/Stripe수수료/플랫폼수수료/조정 → 계정
POST/api/v1/me/charity/xero/sync/{payoutId}Receive Money 전송 (수입 라인 + 음수 수수료 라인), 결과 기록
GET/api/v1/me/charity/xero/historysync 이력

✅ 프론트 상태 — 화면은 이미 있습니다
Growth 데모 대시보드의 Accounting 탭에 Xero 연결 카드, 계정 매핑, payout summary 테이블, Send to Xero 버튼, sync history가 mock 데이터로 배포되어 있습니다. API 스펙이 위와 달라져야 한다면 프론트를 맞추면 되니 편하게 제안해 주세요.
