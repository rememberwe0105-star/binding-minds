안녕하세요, 백엔드 팀 여러분. Growth 유료 기능 하나가 더 확정되어 공유드립니다. 🙏

기부자가 기관 또는 특정 프로젝트를 위해 개인 모금 페이지(fundraiser)를 만들어 친구·가족·whānau·커뮤니티에 공유하는 P2P 펀드레이징입니다. 프론트 데모(생성 모달·기관/프로젝트 페이지 섹션·대시보드 관리 탭)는 배포 완료됐고, 기존과 같은 게이트 패턴으로 배선되어 엔드포인트가 열리면 자동으로 실연동됩니다.

정책 (확정)

구분동작
Public생성 시 pending → 기관 승인 후 기관/프로젝트 공개 페이지에 게시. 부적절한 내용/사진은 기관이 Decline (기관에게 최소한의 컨트롤)
Private링크로만 공유, 공개 페이지 미노출, 승인 없이 즉시 생성
기관 관리자대시보드 "Supporter Fundraisers" 탭에서 전체 목록 조회/필터/승인/거절
플랜 게이팅대상 기관이 plan=paid(Growth)가 아니면 생성 403 + 안내

P2 요청 API

MethodEndpoint설명
POST/api/v1/fundraisers기부자가 펀드레이저 생성 (로그인 필요)
GET/api/v1/charities/{slug}/fundraisers공개 목록 — approved+public만 (?campaign={slug}로 프로젝트 필터)
GET/api/v1/me/charity/fundraisers기관 관리자 — 전체 목록
PATCH/api/v1/me/charity/fundraisers/{id}{"status": "approved" | "declined"}

생성 요청 body — 프론트가 이미 전송하는 형태

POST /api/v1/fundraisers
{
  "charitySlug": "forest-and-bird-nz",
  "campaignSlug": "restore-native-forest",   // project-level일 때만
  "level": "project",                         // "organisation" | "project"
  "title": "Hana's 40th Birthday — trees instead of gifts",
  "goalAmount": 1000,
  "message": "Instead of presents this year…",
  "visibility": "public"                      // "public" | "private"
}

응답: { "id": "fr_xxx", "shareUrl": "https://…/f/{share_slug}" }

백엔드 작업 체크리스트

  • fundraisers 테이블: owner(user) · charity · campaign? · level · title · goal_minor · message · visibility · status(pending/approved/declined) · share_slug · 생성/승인 시각
  • 생성 로직: private → 즉시 approved(비공개) / public → pending + 기관에 알림(이메일 권장)
  • 개인 모금 페이지용 share_slug 발급 — 프론트가 /f/{slug} 페이지를 다음 단계에 구현
  • 펀드레이저 경유 기부 집계 대비: checkout에 fundraiserId 추가 시 raised/supporters 집계 (스키마만 염두 — 다음 단계)
  • Growth 게이팅: 대상 기관 plan=paid 확인
