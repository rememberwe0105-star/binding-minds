A Accounting & Xero Sync (Growth 유료 기능)

Stripe가 기관 계좌로 입금하는 payout이 어떤 기부금과 수수료로 구성됐는지 정리해, NZ에서 가장 널리 쓰이는 회계 소프트웨어 Xero로 보내는 기능입니다. 방식은 플랫폼 → Xero API 직접 단방향 sync로 확정 (Zapier 아님 — Donorfy/Keela 표준 패턴). Xero에서 읽는 것은 계정과목(COA)뿐이고, 거래는 플랫폼→Xero 한 방향입니다.

A-2. 환불 · chargeback 기록 (조정 라인)

  • webhook charge.refunded, charge.dispute.* → 해당 payout에 조정 내역 기록
  • 플랫폼 내 환불 요청/승인 기능은 만들지 않습니다 — 기관이 Stripe 대시보드에서 직접 처리 (Donorbox 운영 모델). 우리는 기록·표시만 합니다

B 기관 프로필 메타데이터 (난이도 낮음)

Charities 목록에 정렬 옵션(Recently updated / Name A–Z / Claimed profiles first)이 추가됐습니다. 지금은 프론트 로컬 데이터로 동작하며, 기관 API 연동 시 아래 필드가 응답에 포함되면 실데이터 정렬로 자연스럽게 전환됩니다.

  • 기관 목록/상세 응답에 profile_updated_at 추가 — 프로필 정보가 마지막으로 관리/갱신된 시각
  • 기관 목록/상세 응답에 claim_status 추가 (unclaimed | claimed | partnered) — 기존 승인 파이프라인 상태와 매핑
  • 프로필 수정·승인·티어 변경 등 관리 이벤트 발생 시 profile_updated_at 갱신

C P2P Supporter Fundraisers (Growth 유료 기능)

기부자가 기관 또는 특정 프로젝트를 위해 개인 모금 페이지(fundraiser)를 만들어 친구·가족·whānau·커뮤니티에 공유하는 P2P 기능. Growth 플랜 기관 전용.

정책 (확정)

구분동작
Public생성 시 pending → 기관 승인 후 기관/프로젝트 공개 페이지에 게시. 부적절한 내용/사진은 기관이 Decline
Private링크로만 공유, 공개 페이지 미노출, 승인 없이 즉시 생성
기관 관리자대시보드 "Supporter Fundraisers" 탭에서 전체 조회/필터/승인/거절

요청 API

MethodEndpoint설명
POST/api/v1/fundraisers기부자가 펀드레이저 생성 (로그인 필요)
GET/api/v1/charities/{slug}/fundraisers공개 목록 — approved+public만 (?campaign={slug} 프로젝트 필터)
GET/api/v1/me/charity/fundraisers기관 관리자 — 전체 목록
PATCH/api/v1/me/charity/fundraisers/{id}{"status": "approved" | "declined"}

생성 요청 body — 프론트가 이미 전송하는 형태

POST /api/v1/fundraisers
{
  "charitySlug": "forest-and-bird-nz",
  "campaignSlug": "restore-native-forest",   // project-level일 때만
  "level": "project",                         // "organisation" | "project"
  "title": "Hana's 40th Birthday — trees instead of gifts",
  "goalAmount": 1000,
  "message": "Instead of presents this year…",
  "visibility": "public"                      // "public" | "private"
}
응답: { "id": "fr_xxx", "shareUrl": "https://…/f/{share_slug}" }

백엔드 작업 체크리스트

  • fundraisers 테이블: owner(user) · charity · campaign? · level · title · goal_minor · message · visibility · status(pending/approved/declined) · share_slug · 생성/승인 시각
  • 생성 로직: private → 즉시 approved(비공개) / public → pending + 기관에 알림(이메일 권장)
  • share_slug 발급 — 프론트가 /f/{slug} 페이지를 다음 단계에 구현
  • 펀드레이저 경유 기부 집계 대비: checkout에 fundraiserId 추가 시 raised/supporters 집계 (스키마만 염두 — 다음 단계)
  • Growth 게이팅: 대상 기관 plan=paid 확인, 아니면 생성 403
✅ 프론트 상태
Growth 데모(/auth → Demo — Charity (Growth Plan)) 대시보드 Supporter Fundraisers 탭(통계·필터·승인/거절)과, Restore Native Forest 프로젝트 / Forest & Bird 기관 페이지의 Start a fundraiser 모달·섹션이 배포됨.
